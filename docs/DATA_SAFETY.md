# 資料安全與版本一致性

第一階段只修復成品保留、Gemini快取、工作區保護與內容版本。照片上傳、時間軸、動畫、AI標籤、PNG、BGM及既有FFmpeg管線維持原架構；ZIP仍使用「儲存專案檔 → 下載」。

## 四種內容版本

`studio/versioning.py`與`frontend/content-version.js`共用`frontend/content-schema.json`，以SHA-256產生`cv1-...`內容識別。

| 狀態 | 意義 |
| --- | --- |
| 前端`draft.contentVersion` | 此刻瀏覽器完整草稿的內容版本，修改後即時更新 |
| 後端`content_version` | 已驗證並套用的內容版本 |
| `zip_version` | 最近成功產生ZIP所使用的內容版本 |
| `mp4_version` | 最近成功輸出MP4所使用的內容版本 |

版本包含照片順序、時長、構圖、兩套模板片段與標籤、PNG圖層、封面／正文／LOGO、音樂設定、輸出解析度、媒體SHA-256及模板／字型／渲染規則識別。包含未使用素材庫及另一模板的設定，因為ZIP保存整個工作區；這些內容改變也會保守標記既有影片為舊版。

不包含游標、播放時間、選取、API用量、登入狀態、Secrets、回應nonce、時間戳記、預覽data URL、文字光柵或遷移標記。素材只在伺服器以bytes計算摘要；前端只接收摘要，不需逐次重新雜湊大圖片或音檔。

物件鍵固定排序，數字採共用IEEE754格式，因此`1`／`1.0`、負零、JSON縮排、鍵順序及十六進位字色大小寫不會製造不同內容版本。標籤文字前後空白沿用既有後端trim規則。無效草稿仍可本地保存，但套用前仍須通過原本驗證。

`revision`保留作傳輸衝突檢查，`nonce`用於交易去重，`seq`保護提交後的新編輯。內容不變時不推進內容版本，無變更套用也不推進revision。回到相同內容會得到原本的hash，不因操作時間產生新版本。

`pipeline`識別僅在實際渲染規則改變時升級；註解或熱更新協定版本變更不會單獨改變內容版本。模板、排版及字型摘要變更會令成品與新環境分開，跨Windows／Cloud的字型差異仍可能改變成片。

## 成品保留

以前`invalidate()`、同步及開始輸出直接清除`output`。目前保留最近一次成功MP4及ZIP；修改只使它們與草稿版本不同，不刪除bytes。新的MP4成功後才透過`complete_export()`替換；輸出／打包失敗保留上一個成品。

輸出job與ZIP保存job帶來源版本，執行前驗證仍符合來源設定。前端提交版本也須符合伺服器對完整驗證後資料重新計算的版本，不能靠客戶端自稱版本決定成品來源。

編輯器上方即時顯示草稿、已同步、ZIP、MP4及備份狀態。Python下載區顯示來源版本；已套用內容不同時顯示舊版提醒。Python無法逐次知道尚未提交的前端修改，因此下載區明示以編輯器即時版本為準，不聲稱原有成片包含最新草稿。MP4檔名附來源版本。

## 清空、登出與匯入取代

1. 空工作區直接執行，不增加確認。
2. 有內容時發出一次`guard_request`，前端短暫鎖定內容、保留草稿，回傳目前內容版本；不要求先套用、不驗證或提交尚未完成的編輯。
3. 與已確認ZIP備份版本相同時自動繼續，不需再按確認。
4. 尚未備份、版本不同或無法確認時，提供取消與明確繼續；前端不回覆時保留保守的「仍要繼續」入口。
5. 取消只清除本次檢查／待匯入資料；照片、文字、PNG、BGM、成果與登入狀態保留。

同次檢查依request ID去重；舊工作階段、舊request或過期revision回覆不會核准新操作。檢查及確認期間暫停會改變工作區的按鈕。正常文字輸入、拖曳、切換照片不會出現提示或持續觸發Python。

ZIP備份分成「已產生」、「已提出下載請求」、「使用者已確認此版本ZIP已儲存」三種狀態。前兩者不會設定`backup_confirmed_version`，因為網站無法證明瀏覽器已把檔案存到電腦。下載請求後可按一次「我已確認此版本ZIP已儲存」。確認的是該ZIP版本，不是之後的新草稿。

匯入完整驗證成功的ZIP後，以解出的實際內容重算工作基線；來源ZIP本身可作此基線備份。檔案裡的自稱版本或備份狀態不直接採信。ZIP格式仍為1，未帶版本欄位的舊專案可開啟；新工作階段防止舊草稿覆蓋匯入內容。內建品牌模板／字型仍依執行環境，不新增雲端保存。

已有MP4但來源版本未知的舊工作階段不會丟失影片；介面保守標記來源未知，重新輸出成功後建立可核對版本。

## Gemini快取

原本`ai_results[photo_id]`只有最近一次模型結果，未完成判斷忽略其他模型的有效快取。現在從`ai_cache`以照片內容、模型、提示詞版本、實際提示詞、Pydantic schema、生成參數、圖片預處理及座標正規化規則識別查找。

A → B → A時可再次使用A的有效快取；切換模型及普通rerun本身不呼叫API。照片、提示詞或條件不同時失效。失敗的強制刷新仍保留pending，不能拿舊成功結果冒充本次刷新成功。既有結果資料格式與人工標籤保留／交付去重機制不變。

原有未完成補查仍只補未完成照片。需要忽略成功快取時，明確勾選「強制重新分析所選照片（忽略快取，會消耗額度）」再按分析；不因勾選或切模型自動呼叫。舊協定快取缺少完整條件識別時不冒充有效快取，但已產生的標籤仍保留。
