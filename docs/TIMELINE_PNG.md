## 操作

1. 上傳照片或載入五張測試圖。下方時間軸包含照片、文字與 PNG，重疊素材會排列在同軌的不同列。
2. 點擊秒數刻度並拖曳可跳轉；紅線是播放指針。鍵盤左右鍵每次移動一影格；時間軸縮放可展開較長的影片。
3. 點素材選取，拖中央移動，拖左右邊緣調整時間。照片拖中央調整順序；文字仍附屬於自己的照片。
4. 在 PNG 素材庫點縮圖立即加入圖層；自己的 PNG 先於上方「上傳 PNG 素材」選檔，再按「加入 PNG 素材庫」。
5. 點時間軸的 PNG 自動選取並顯示設定；目前時間不在該素材區間時才跳到開始。暫停時直接拖畫面中的 PNG 移動，右下方方形把手等比例縮放，上方圓形把手旋轉。淡入起點完全透明時，可將指針稍往後移；設定面板可直接調時間、位置、透明度、層級、進出場動畫。
6. 「移到最上層／最下層」同時處理文字與 PNG。亦可輸入層級，數值越大越前；同層級時依素材順序繪製，PNG 排在文字後面。
7. 播放預覽會套用動畫並隱藏操作框。按「套用變更」整批保存至 Python；按任何輸出入口會先自動套用最新照片、文字與 PNG。

預設包含兩個自行繪製的透明幾何素材：箭頭與價格框，可商業使用。LOGO 由使用者自行提供。開發者將靜態 PNG 放進 `assets/overlays/`，重啟服務／建立新工作階段即可自動讀取，不需改素材清單。可用 `scripts/create_overlay_samples.py` 重建內附素材。

## 唯一時間資料與縮短規則

照片只存順序與 `duration`，從前到後連續播放；不另存第二套照片開始時間。文字保留既有照片內 `start/end`，時間軸顯示時加上照片開始秒數。

PNG 為獨立全片素材，存 `id/type/source/start/duration/layer/x/y/width/scale/rotation/opacity/animation/exit_animation/enter/exit`。`source` 指向工作階段素材庫；PNG 可以跨照片與彼此重疊。結束時間由 `start + duration` 推導，不重複保存。`x/y` 為畫面中心比例，`width` 為相對畫面寬度，縮放維持原 PNG 長寬比。新增其他素材類型可擴充此投影模型，本次不實作音樂／影片軌。

- 時間軸拖曳以 30 FPS 的一影格為單位。
- 照片改長：原有文字時間維持；改短：超過照片結尾的文字截短，最短保留一影格，進場長度一併限制。
- 照片排序：文字跟著照片，PNG 的全片秒數維持。
- 照片軌右邊界改該照片長度；左邊界改與前一張的共用分界，維持兩張總長。第一張左邊界固定為 0。照片不支援空白間隙／獨立重疊。
- 全片變短：PNG 結束超出部分截短；開始也超出結尾時移到最後一影格，進出場時間按比例縮短。刪掉所有照片會移除全部 PNG 圖層，但素材庫仍可再次使用。
- 靜止位置依旋轉後包圍框限制在畫面內；素材過大時縮至可完整放入的尺寸。滑入／滑出動畫刻意從畫面外移動，並由畫面邊界裁切。

## 同步與輸出

時間軸及 PNG 共用原有 `StudioDraft`，所有移動、裁切、新增、刪除、樣式與圖層調整只修改 JavaScript 本地狀態。`sessionStorage` 保存純設定，不存照片／PNG 圖片內容。切換照片、上傳素材觸發的一般 Streamlit rerun、元件重建皆保留未套用草稿。

只有套用及輸出握手傳送整份設定。協定版本升為 3；PNG 先驗證，照片與 PNG 都成功才一起更新 Python。唯一事件 ID／revision 防止重複與舊回覆覆蓋後續拖曳。圖片由工作階段素材庫提供，前端不傳送可任意讀取的檔案路徑。

PNG 與文字共用圖層排序，Canvas 與 Python 使用相同幾何與動畫公式。出場採既有進場函式反向播放。FFmpeg 保留原本逐影格管線、30 FPS、H.264 與暫存清理；PNG 在輸出前縮放／旋轉準備一次，不在每影格重做原始素材解碼。瀏覽器錄製也使用同一個畫布。

素材只存在工作階段記憶體；整頁重新整理、連線中斷、服務重啟可能遺失圖片。這不是永久專案存檔。

## 上限

- 靜態 PNG，每張 5 MB、800 萬畫素；保留 Alpha，拒絕 APNG、損壞檔與改副檔名的非 PNG。
- 素材庫最多 24 個，預設及上傳素材合計最多 40 MB；全片最多 32 個圖層。
- 每 PNG 至少一影格，進場／出場各最多 3 秒，合計不超過持續時間。
- 保留原照片最多 12 張、全片 120 秒、Full HD／30 FPS 目標。
- 沒有素材庫個別刪除／替換功能；可刪除畫面圖層，或清空工作階段移除上傳素材。

## 自動化與實際驗證

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/*.test.cjs
.\.venv\Scripts\python.exe -m pip check
```

33 項 Python、22 項 Node 測試涵蓋既有 AI／照片／標籤，以及 PNG 格式、Alpha、時間區間、跨照片與重疊、圖層排序像素、失敗原子性、草稿恢復及輸出握手。前端合成事件測試包含 500 次畫布移動、100 次時間軸移動，沒有在拖曳中送 Python 事件。這是合成 DOM 測試，不等同實體裝置效能測量。

`tests/test_overlays.py` 真正生成 1080×1920／30 FPS／H.264 的兩秒 MP4：兩張照片、透明 PNG、旋轉、透明度、進出場與重疊圖層。完整解碼，擷取四個時間點，與預期影格及 PNG 區域像素比對；確認跨照片仍可見。另比較 35 組幾何案例與七種動畫在八個時間點的 Python／JavaScript 結果。Streamlit AppTest 驗證輸出前最新 PNG、rerun 保存與清空，並實際產生 360p MP4。

實際 Chromium 瀏覽器已操作：加入兩個預設 PNG、使用者檔案選擇器上傳 PNG、畫布移動／角落縮放／旋轉把手、圖層移到下方、修改動畫、PNG 跨照片與重疊、拖時間軸中央及左右邊界、拖播放指針，並確認上傳及 Streamlit rerun 後未套用內容保留。網頁實際輸出五張照片、三個 PNG 的 20 秒 Full HD MP4，耗時約 16 秒；影片載入後 readyState=4、1080×1920、duration=20，顯示下載按鈕。本次沒有再次驗證該按鈕下載後的檔案，解碼／像素驗證使用前述真實自動化輸出。AI 回歸本次使用 Mock，沒有新增真實 Gemini 呼叫，也沒有把 Mock 當成 API 成功。

## 仍需人工驗證

1. 使用公司自己的透明 LOGO 與價格圖，加入三個重疊素材；調整層級與文字交錯，播放並逐段檢查 MP4。
2. 快速反覆拖指針與多個素材，調照片順序／長度後返回；核對文字跟照片、PNG 依全片秒數及尾端截短規則。
3. 不按套用直接輸出，確認最新刪除／旋轉／樣式都有進入下載檔；比較瀏覽器錄製與 FFmpeg 的畫質／動畫。
