# MP4輸出時同時下載ZIP備份

本次從`main`的`df98c0769388136946ed924c12e54cb1b87b0da1`增量修改輸出流程，保留已完成的空間導覽、另外兩套模板、現有編輯器、時間軸、影片渲染器與專案格式。

## 操作

「輸出 H.264 MP4」旁新增預設勾選的「同時下載 ZIP 專案備份」，原本獨立「下載 ZIP」仍在同一列。勾選後按一次輸出，取得點擊當下草稿、自動同步，再用同一份快照製作兩個檔案；完成後先提出MP4下載，再提出ZIP下載。取消勾選則只產生MP4，不建立ZIP。

選項存在目前分頁的輸出控制器與既有sessionStorage草稿中，一般Streamlit rerun／元件重建保留。不觸發逐次Python同步，也不寫進ZIP內容或內容雜湊，不增加專案revision。不同工作階段或無法使用分頁儲存時不保證保留這項偏好；新工作階段預設勾選。

這個勾選框只控制下方FFmpeg輸出，原本另有的瀏覽器錄製功能維持原流程。

## 同版本保證

1. 前端請求有唯一ID、草稿sequence與內容雜湊；輸出選項透過既有protocol 3事件傳送，與影片內容分離。
2. 後端驗證內容與精確ACK後，只建立一份白名單快照。照片／影片／平面圖／音樂bytes保持不可變共用，文字與時間軸設定複製隔離，不保存Secrets或登入狀態。
3. 同一背景工作先建立ZIP，再輸出MP4，各自捕捉錯誤；不是重新讀取Session State製作第二份成果，也不是開兩次渲染。
4. 每個成功成果都記錄同一個`content_version`與請求ID；ZIP的manifest亦記錄該版本。使用者在等待時修改B，正在製作的兩檔仍屬A。
5. 一般案例、前後對比與空間導覽都沿用原本`build_archive()`／`export_video()`；沒有修改渲染核心或新建時間軸。

## 分開管理結果

| 本次結果 | 行為 |
| --- | --- |
| MP4成功、ZIP成功 | 更新兩個成功成果及版本，各自提出下載請求，顯示兩個手動入口 |
| MP4成功、ZIP失敗 | 更新MP4、保留先前成功ZIP，顯示ZIP錯誤與「重試此版本 ZIP」 |
| ZIP成功、MP4失敗 | 更新ZIP、保留先前成功MP4，顯示MP4錯誤，ZIP仍可自動／手動下載 |
| 兩者失敗 | 保留先前成功成果與草稿，顯示各自錯誤 |
| 檔案成功但短效連結建立失敗 | 保留記憶體中的成功檔案，改用原生下載按鈕；不宣稱產生檔案失敗 |

「重試此版本 ZIP」保留一次失敗工作使用的原快照，產生新的重試請求ID，不再次渲染MP4、不重新擷取後續草稿。重試仍失敗時可再次手動重試，沒有自動無限重試。開始新的正常輸出／下載請求或重設工作區後，這份重試快照會釋放。

MP4失敗時重新按主要輸出按鈕，是擷取當時最新草稿的新請求，不會把舊ZIP改稱為新MP4的備份。每個原生下載與短效入口均依實際成功版本顯示；只保留每種格式最近一次成功成果，不提供完整歷史版本庫。

## 下載與安全限制

延伸既有`studio/downloads.py`，允許ZIP與MP4共用同一個`static/downloads/`：64位隨機十六進位檔名、原子寫入、15分鐘短效、30秒清理掃描及320 MB暫存上限。新成果替換、已確認的工作區重設會撤銷舊連結。沒有永久公開連結，沒有把大型影片或ZIP轉Base64傳入元件。

短效網址仍是不經應用程式密碼驗證的持有者連結，請勿轉傳；URL不含金鑰、密碼或原始檔名。伺服器中斷或Cloud重新啟動時，未備份成果仍可能失去。

每個請求的MP4／ZIP分開記錄前端下載收據，**先保存收據，再點下載連結**；一般rerun與元件重建不會重新觸發。兩檔下載請求metadata合併送回Python，避免快速發送兩次元件事件而遺失其中一份收據。舊版單獨ZIP事件仍相容。

瀏覽器可能靜默阻擋第二個自動下載，網站無法可靠確認實體檔案是否已儲存。因此介面顯示「已提出下載請求」，而非「已儲存成功」。若少一檔，點相對應的短效「備用下載MP4／ZIP」；過期、static未啟用或暫存空間不足時，使用下方原有原生「下載 MP4 影片」與「備用：重新下載已產生的 ZIP」。這些入口下載同一份成品，不會重新渲染或換版本。

## 備份確認

自動下載、手動下載、草稿暫存均不會設定`backup_confirmed_version`。使用者確認電腦上ZIP存在後，才按「我已確認此版本ZIP已儲存」。確認A只標記A，後續草稿B仍未備份。沿用既有備份保護，不增加無關確認視窗。

部署後人工驗收：

1. Chrome／Edge在Cloud各勾選輸出一次，確認兩檔是否都出現在下載資料夾；若第二檔被阻擋，確認對應備用入口可下載，不需更動瀏覽器安全設定。

3. 輸出A期間改標題為B，確認兩個成品來源均為A；確認A備份後，B仍顯示未備份。
4. 輸出完成後觸發一般rerun，確認不再自動下載；等待連結過期後，原生備援仍可下載保留在工作階段的成果。
5. 以實際大素材測試Cloud尖峰記憶體與耗時。雙檔會同時保留ZIP與MP4，增加記憶體／暫存負擔；沒有提高任何現有素材、ZIP或下載暫存上限。
