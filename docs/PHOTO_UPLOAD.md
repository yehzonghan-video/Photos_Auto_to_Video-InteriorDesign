# 大照片上傳與自動最佳化

2026-10-13 更新：6000 萬總畫素、80 MB 工作階段容量、3200 萬單張畫素及 15 MB 單張工作檔案，都改成自動最佳化門檻，不再因此直接拒絕一般照片。

## 處理流程

1. 一般照片在門檻內保持原始 bytes，輸出前不因預覽而重新壓縮。
2. 單張過大時建立等比例縮小的工作副本；JPEG 優先嘗試解碼降採樣。工作副本最多 3200 萬畫素、15 MB，必要時依序調整 JPEG 品質及尺寸。
3. 整批工作照片超過 6000 萬畫素或 80 MB，依預算等比例調整工作副本。這些值限制的是處理後的圖片，原先超過上限的照片仍可加入。成功後才整批更新，保留 ID、順序、標籤、構圖、秒數及 PNG 圖層。
4. 編輯器只接收最大長邊 2560、400 萬畫素、2 MB 的 JPEG 預覽，並依工作照片內容快取；文字／PNG 拖曳不會重新生成照片預覽。
5. FFmpeg 仍從伺服器保留的原檔或最佳化工作副本輸出，不使用較小的預覽圖。瀏覽器錄製使用預覽圖，放大裁切時可能較柔；重視畫質請選 FFmpeg。

縮小保留長寬比、不裁掉照片；EXIF 方向先校正。透明照片在預覽及縮小 JPEG 工作副本時合成黑底，與既有照片輸出一致；獨立 PNG 圖層仍完整保留 Alpha，沒有改變其素材限制。

畫面會顯示自動調整後的尺寸。這是另做工作副本，不會改動使用者電腦上的原始檔。一般照片的原檔保存在目前工作階段；超出工作記憶體預算的原始 bytes 不另保留第二份，以免失去最佳化的效果。

## 邊界

- 上傳傳輸上限由 15 MB 提高為每檔 200 MB（初次更新需重啟 Streamlit 才載入 server 設定）；照片張數 12 與影片 120 秒限制仍保留。
- 仍拒絕損壞、非支援格式、動態圖片，保留 Pillow 對極端解壓縮尺寸的保護。
- 捕捉解碼記憶體不足後會嘗試較小工作副本；圖片格式本身需要完整解碼、主機記憶體完全耗盡、傳輸中斷等狀況仍可能失敗，程式不能保證無限大小／數量都能上傳。
- Streamlit 上傳原始檔仍先進入伺服器記憶體；200 MB 是傳輸上限，不是免費 Cloud 的效能保證。照片與工作副本都沒有永久寫入磁碟。
